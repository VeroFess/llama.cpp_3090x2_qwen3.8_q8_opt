# Qwen3.8 27B Q8 on two RTX 3090 GPUs

This fork provides one fail-closed production profile:

```bash
CUDA_VISIBLE_DEVICES=0,1 \
GGML_CUDA_P2P=1 \
GGML_CUDA_ALLREDUCE=nccl \
./build-qwen38-3090/bin/llama-server \
  --model /models/Qwen3.8-27B-Q8_0.gguf \
  --alias Qwen3.8-27B-Q8_0 \
  --profile qwen38-27b-q8-2x3090 \
  --split-mode tensor \
  --ubatch-size 1024 \
  --reasoning off \
  --host 0.0.0.0 \
  --port 8080
```

## Model

The acceptance model is `unsloth/Qwen3.8-27B-GGUF` revision `f1bfb127c64f7072bdd2cad55f258b9c8b2910fe`.

- File: `Qwen3.8-27B-Q8_0.gguf`
- Size: `29047086048` bytes
- SHA-256: `a680f44a06920e5d689774823782006aa3acc8db95750323373b24139b67e348`

The profile scans all large matrix tensors and rejects a model below the Q8 quality floor. Norms, scales, biases, and other small tensors can keep their GGUF types.

## Build

```bash
cmake --preset qwen38-3090-release
cmake --build --preset qwen38-3090-release -j
```

The preset compiles CUDA only for SM86 and enables FlashAttention, CUDA graphs, NCCL, and `GGML_QWEN38_2X3090`.

## Hardware checks

The server requires exactly two visible RTX 3090 devices, 24 GB class VRAM, and compute capability 8.6. CUDA peer access is detected at startup. Tensor mode uses NCCL over the enabled peer path; layer mode retains bounded pinned host staging as its fallback.

The startup log and model metadata report `pinned_host_staged` or `cuda_peer`. Pageable host staging is not supported.

On the acceptance host, `nvidia-smi topo -m` reports `PHB`, NVLink is inactive, and CUDA P2P read/write is available after the BIOS, VBIOS, and driver update. Resizable BAR exposes the full 32 GB BAR1 aperture on both GPUs.

Run the container with both devices visible:

```bash
QWEN38_MODEL=/models/Qwen3.8-27B-Q8_0.gguf docker compose -f docker/qwen38-compose.yml up --build
```

## Profile behavior

- Tensor split with an enforced 1:1 split is the recommended P2P fast path. Layer split remains available as the compatibility path.
- The Qwen3.8 output head is mirrored in tensor mode so target and MTP draft sampling stay on the GPUs. Model trunk and paged KV tensors remain sharded.
- Single-sequence contiguous page runs use the Q8 tensor-core FlashAttention path for both prefill and generation.
- Native context limit of 262144 tokens.
- Up to eight resident sequences in one unified token pool.
- Q8_0 K and V cache with no automatic precision fallback.
- Tensor-sharded Q8 paged attention, FlashAttention, continuous batching, prompt reuse, exact recurrent checkpoints, and MTP enabled.
- MTP drafts at most two tokens.
- At most two exact recurrent checkpoints per resident slot with a 2048 MiB host cache budget.
- Context shift, YaRN, row split, CPU KV, image input, and video input are rejected.

`--max-model-len` is the input plus output limit for one sequence. It does not allocate eight copies of the maximum context.

## Capacity modes

The production profile always uses Q8_0 KV. TurboQuant and TCQ remain available outside the profile as explicit capacity modes. They are never selected after an allocation failure.

## Autotuning

`llama-qwen38-tune` writes a schema-v2 cache keyed by the model and GGUF inventory SHA-256 values, source commit, fork manifest, CUDA toolkit, driver, GPU UUIDs, power limits, PCIe topology, Q8 KV codec, and resident sequence limit. Placement ratios include the two MTP layers, so a 36/28 target split is encoded as `36/30` for the 66 placed layers.

```bash
python3 -B tools/llama-qwen38-tune \
  --model /models/Qwen3.8-27B-Q8_0.gguf \
  --llama-bench ./build-qwen38-3090/bin/llama-bench \
  --llama-gguf ./build-qwen38-3090/bin/llama-gguf \
  --evidence benchmark-production-full.json \
  --output qwen38-tuning.json
```

A dry run records the key and candidate matrix but sets `validated` to false. A non-dry run also requires repeated `--evidence benchmark.json` arguments covering the formal server workloads, pinned-host byte balance, pipeline depth, CUDA Graph activity, and sampled VRAM peaks. The server rejects unvalidated, malformed, tampered, wrong-model, or out-of-bounds caches.

```bash
./build-qwen38-3090/bin/llama-server \
  --model /models/Qwen3.8-27B-Q8_0.gguf \
  --profile qwen38-27b-q8-2x3090 \
  --autotune quick \
  --autotune-cache qwen38-tuning.json \
  --host 0.0.0.0 \
  --port 8080
```

The server watchdog defaults to 120 seconds for one decode or synchronize call. `LLAMA_CUDA_WATCHDOG_MS` can raise this limit, but values below 30 seconds are rejected. A timeout exits with code 70; an unrecoverable compute error exits with code 71 so systemd or Docker can restart a clean CUDA context.

## State and sessions

Per-sequence checkpoints save Q8 attention pages and exact FP32 recurrent state. Full-state save/restore writes each unique shared attention page once, records each sequence's page indices, and rebuilds shared-prefix references and tail CoW layout on restore. State files never contain a lower-precision recurrent representation.

## Driver recovery

After an NVIDIA package upgrade, verify that the loaded module and user library have the same version before starting a new container:

```bash
cat /proc/driver/nvidia/version
nvidia-smi
```

If they differ, stop GPU containers and reboot the host. Do not validate performance with mixed driver versions.

## Common failures

- `requires exactly two visible CUDA devices`: expose only GPU 0 and GPU 1 to the container.
- Unexpected `cuda_peer` or `pinned_host_staged` mode: check PCIe topology, ACS, IOMMU policy, and Resizable BAR configuration.
- `core matrix below the Q8 quality floor`: use the pinned Q8_0 GGUF.
- `runtime context does not match the profile limits`: remove conflicting context or parallel options.
- MTP initialization failure: verify that the GGUF contains its `nextn` tensors.
